# Командная динамика — модель v1.1, контракт JSON

Для сайтов, которые получают расчёт от astronavtapi.ru и интерпретируют его.
API 3.11.0. Алгоритм согласован 2026-09-10.

## Что это и чего это не

Четыре **операционные характеристики** участия человека в командном процессе:
как он передаёт информацию, как её обрабатывает, как переходит к действию и
как исполняет. Модель — проекция методологии командной динамики на
терминологию Human Design.

Это **не** психологическая диагностика, **не** психометрия, **не** оценка
компетентности и **не** основание для кадровых решений. Веса — наш выбор, а
не свойство системы; правила со статусом `hypothesis` помечены в каждом ответе.

## Где взять

| Запрос | Где лежит блок |
|---|---|
| `GET /calculate` | `team_dynamics` в корне ответа |
| `POST /v2/calculate` | `team_dynamics`; работает `include: ["team_dynamics"]` и точечные пути (`team_dynamics.axes.decision`) |
| `POST /analyze/team-dynamics` | `team_matrix` — матрица команды и `team_matrix.profiles[имя]` — тот же блок по каждому |

`time_precision_min` (минуты, 0–1440) — насколько точно известно время
рождения. С 5 минут добавляется `team_dynamics.time_stability`.

## Четыре оси

| Ось | Первый полюс (A, индекс → 0) | Второй полюс (B, индекс → 100) |
|---|---|---|
| `transfer` Передача информации | `structured` **S** Структурированная | `emergent` **F** Неформальная |
| `processing` Обработка информации | `consistent` **D** Фиксированная | `contextual` **R** Относительная |
| `decision` Принятие решений | `internal` **C** Компетентный | `relational` **H** Гармоничный |
| `execution` Исполнение | `planned` **P** Целенаправленное | `adaptive` **A** Импульсивное |

`code`: `F·D·H·P·I1` — буквы полюсов по порядку осей и Integration; `–`, если
полюс не присвоен.

## Поля оси

```json
"transfer": {
  "index": 71.4,              // 0 — первый полюс, 100 — второй
  "evidence_a": 1.0,          // сумма весов за первый полюс
  "evidence_b": 4.0,          // сумма весов за второй
  "confidence": 0.71,         // (A+B)/(A+B+2): 0.33 — один признак, 0.5 — два, 0.71 — пять
  "band": "moderate_b",       // strong_a | moderate_a | mixed | moderate_b | strong_b | insufficient
  "side": "b",                // a | b | null
  "pole": "emergent",
  "letter": "F",
  "pole_label_ru": "Неформальная",
  "pole_meaning_ru": "…",     // допустимая формулировка для отчёта
  "hypothesis_share": 0.0,    // доля веса на правилах со статусом hypothesis
  "evidence": [ {"kind":"channel","key":"11-56","side":"b","weight":2.0,"status":"supporting","note_ru":"…"} ],
  "population": {"pole_pct": 18.8, "index_percentile": 99.63},
  "field": {"basis":"throat","defined":true,"stability":"stable"}
}
```

**Индекс** = 100 × (B + 1) / (A + B + 2). Единицы сглаживают тонкие случаи:
один признак не даёт крайнего значения.

**Полосы:** `< 25` выраженный первый · `25–45` умеренный первый · `45–55`
смешанный · `55–75` умеренный второй · `> 75` выраженный второй.
Полоса и полюс присваиваются при A + B ≥ 2; иначе `insufficient`.
Исключение — Исполнение только по стрелке Perspective (см. ниже).

**`index_percentile`** — доля популяции с индексом не выше этого. 99.6 на
Передаче значит: неформальнее этого человека — 0.4% людей.

**`pole_pct`** — доля популяции с этим полюсом. Пригодна для фраз вида «такой
профиль у 18.8% людей».

## Правила по осям

### Передача — `transfer`
A: Горло определено 1 · 43–23 1 · 17–62 0.5 · 31–7 1 · 8–1 1.
B: Горло открыто 1 · 11–56 2 · 35–36 2 · 12–22 2 · 33–13 1 · 20–10 1 · 20–34 0.5 · 20–57 0.5.
`field.stability`: `stable` — способ выражения воспроизводим в разных
командах; `conditioned` — зависит от окружения.

У 44% людей срабатывает только признак Горла → `insufficient`. Это честный
результат: определённое Горло само по себе не означает структурированную
коммуникацию.

### Обработка — `processing`
A: Ajna определена 2 · 63–4 3 · 43–23 2 · 17–62 2 · 61–24 1 · висячие ворота 4, 17, 43 по 1.
B: Ajna открыта 2 · 64–47 2 · 11–56 0.5 · висячие ворота 47, 64, 11 по 1.
Висячие — ворота активны, а канал оси не замкнут. Статус `hypothesis`.

### Решение — `decision`
Только Authority. Открытые центры не участвуют.

| Авторитет | Сторона, вес | `mode` | Индекс |
|---|---|---|---|
| сакральный | A 3 | `response` | 20 |
| селезёночный | A 3 | `instant` | 20 |
| эго (манифест. и проецир.) | A 3 | `will` | 20 |
| самопроецированный | A 2 | `articulated` | 25 |
| эмоциональный | B 2 | `delayed` | 75 |
| ментальный | B 3 | `external` | 80 |
| лунный | B 3, hypothesis | `lunar` | 80 |

`field.entry_condition` — условие входа по типу: `response`, `invitation`,
`inform`, `lunar_cycle`.

**`integration_reading`** — чтение Решения вместе с Integration:

| | I1 — механизм замкнут | I2–I4, R — собирается в контакте |
|---|---|---|
| Компетентный | `internal_closed` — переходит к действию сам | `internal_bridged` — решение внутреннее, окончательно собирается при участии других |
| Гармоничный | `relational_closed` — нужна пауза, время, а не люди | `relational_bridged` — нужны и пауза, и контакт |

Доли в популяции: 22.7% / 23.0% / 17.8% / 36.4%.

### Исполнение — `execution`
A: 5–15 2 · 9–52 2 · 42–53 2 · 46–29 2 · 54–32 1 · Perspective Left 1.
B: 20–34 2 · 20–57 2 · 34–57 1 · 34–10 1 · 3–60 1 · 38–28 1 · Perspective Right 1.
Root и Sacral не участвуют.

`basis`: `channels` или `perspective_only`. У 32% людей нет ни одного канала
этой оси — полюс даёт стрелка Perspective. Тогда полюс присваивается, но с
флагом `perspective_only` и статусом hypothesis. Формулировка для отчёта —
осторожная («по косвенному признаку»).

`perspective.confidence: low` — стрелка у границы тона; добавляется флаг
`perspective_near_boundary`.

## Integration — `integration`
`code`: `I1` одно определение · `I2`–`I4` разделённое · `R` рефлектор.
Не ось и не шкала: split не «хуже» и не «зависимее» single.

## Флаги — `flags[]`
`insufficient`, `mixed`, `perspective_only`, `perspective_near_boundary`,
`hypothesis` (лунный авторитет). Каждый несёт `text_ru`, пригодный для
раздела «ограничения профиля».

## Устойчивость ко времени — `time_stability`
При `time_precision_min ≥ 5` карта пересчитывается в окне неточности.
`axes[ось].pole_stable = false` — полюс меняется в пределах заявленной
точности; не утверждать его в отчёте. Ось Решения к времени чувствительнее
остальных.

## Команда — `POST /analyze/team-dynamics`

| Поле | Что это |
|---|---|
| `matrix.rows[]` | участник × 4 оси: индекс, полоса, буква; режим Решения; основание Исполнения; оси, неустойчивые ко времени |
| `axes_summary[ось]` | средний индекс, разброс, min–max, кто на каком полюсе |
| `team_code` | полюс большинства по каждой оси |
| `risk_hypotheses[]` | все участники с полюсом — на одной стороне (от 3 человек); текст риска и вероятность такого состава случайно |
| `overrepresentation[]` | перекос полюса или режима Решения против популяции; `level: robust` (p < 0.0025) — можно говорить клиенту, `signal` (p < 0.05) — только внутренняя пометка |
| `tests_run`, `expected_false_signals_at_0_05` | сколько проверок сделано и сколько ложных сигналов ожидаемо |
| `absence` | отсутствие полюса или режима; оценивается только с 8 участников |
| `polarization[]` | ось делится на две группы по 2+ человека — описательно |
| `bridging[]` | кто чей разрыв Integration замыкает в очной работе |

## Стоп-лист для интерпретации

1. «Вы структурированный человек» — свойство приписывается человеку, а не участию в процессе.
2. Проценты как вероятность поведения. Допустимы только доля в популяции и p-value перекоса.
3. «В команде нет X» при n < 8.
4. «Split = зависимость», «triple сильнее split».
5. «Эмоциональный авторитет = нужна групповая гармония». Это отложенность решения, а не потребность в согласии.
6. «Открытый центр = слабость».
7. Мистические и судьбоносные трактовки.
8. «Кандидат не подходит на роль».
9. Причинные утверждения («поэтому он срывает сроки»).

## Что не проверено

Веса не откалиброваны на размеченных данных. Проверка — слепая разметка
25–40 человек с точным временем рождения (рейтинг Rodden AA/A) по биографии
**до** расчёта и сравнение с расчётом; заранее зафиксированные альтернативы
(например, Perspective в Исполнении с весом 0 против 1).
